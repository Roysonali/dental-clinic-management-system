# ADR-002: Weekly Recurring Schedule over Dynamic Scheduling

**Status:** Accepted

## Context

Doctors need to define working hours for appointment availability. Two approaches: weekly recurring templates or date-specific entries.

## Decision

Store schedules as weekly template entries in normalized `doctor_schedules` table (day_of_week, session_type, start_time, end_time).

## Alternatives

1. **Date-specific schedules** — Flexible but complex CRUD. Requires generating future entries.
2. **Weekly templates (chosen)** — Simple CRUD. Dental clinic schedules are weekly-recurring. on_leave toggle handles exceptions.

## Advantages

- Simple CRUD — create once, applies every week
- Easy to query — SELECT by day_of_week
- Follows existing DensCare clinic hours pattern
- Efficient overlap detection with composite indexes

## Disadvantages

- Cannot model irregular one-off changes
- Date-specific overrides require future ScheduleOverride entity
- Does not handle holiday closures (clinic-level concern)

## Consequences

- MVP uses weekly templates + simple on_leave toggle
- Future Phase A will add ScheduleOverride entity
- Appointments module queries doctor_schedules for availability
